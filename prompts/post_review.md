# post_review — 你的初稿 → 可发布

你写完初稿后调用。粘贴初稿，或指向 `data/drafts/` 里的文件。

## 输入

1. 你的初稿
2. `config/settings.yaml` 的 `identity` 段（niche / angle / own_content_language / avoid_topics）
3. 若初稿源自某个晨报选题，读对应的 `data/digests/*.md` 段落

## 检查顺序（按此顺序，前面的不过关就别管后面的）

### 1. 事实核查 —— 最高优先级

初稿里每一个数字、日期、项目名、引用、监管条款：
- 标出来源。**没有来源的，标红要求你补，或者删掉。**
- 我可以帮你去核实（WebSearch/WebFetch），但**不会替你猜一个看起来合理的数字**。
- RWA 领域尤其容易错：TVL、代币化规模、监管文件编号、生效日期。
  这类数字错了，账号可信度直接归零，而且圈内人会抓。

### 2. 钩子（第一行）

X 的折叠线在第 1-2 行。第一行决定 90% 的完读率。

给出 **3 个不同的钩子变体**，各走一条路：
- `反共识`：直接说一个和主流叙事相反的判断
- `具体损失`：不说抽象风险，说谁在什么时候亏了多少钱
- `信息差`：第一行就给一个读者不知道的事实

禁止的钩子：
- "最近 RWA 很火" / "今天聊聊…" / "很多人问我…"
- 提问式但答案是显然的（"你知道 RWA 最大的问题是什么吗？"）
- 承诺式（"看完这篇你就懂了"）
- 任何需要读完上文才有意义的开头

### 3. 结构

- **长推串**：每条推文必须能独立成立，且末尾有拉力进入下一条。
  第 2-3 条是流失最严重的地方，把最硬的料放这里，不要放在第 7 条。
- **单帖**：一个论点，一个证据，一个转折。超过 3 个论点就拆成推串。
- 检查是否有"废话段落"：删掉后不影响论证的，直接删。

### 4. 语言

- 按 `own_content_language`。中英混排时，术语保留英文原文（tokenization 不译成"代币化"要看语境，圈内两种都用）
- 砍掉：其实、说白了、众所周知、不难看出、值得一提的是
- 砍掉所有"我觉得可能也许"式的软化，除非你真的不确定
- 句长交替。连续三个长句 = 读者疲劳

### 5. 合规与风险

- 命中 `avoid_topics` 的，警告
- 不构成投资建议的边界：RWA 内容极易滑向荐股语气。指出具体是哪句话
- 点名批评具体项目/个人时的法律与拉黑风险，明确提示，**由你决定**

### 6. 发布策略

- **时间**：基于 `data/raw/` 里名单账号的实际活跃时段计算，给出具体时间和理由。
  数据不足时说"数据不足"，不要编一个"最佳发布时间"。
- **话题标签**：0-2 个。RWA/加密圈的话题标签效应弱，堆标签显得像营销号。
  如果建议加，说明为什么这个标签此刻有流量。
- **首评策略**：链接放首评而非正文（外链降权），并写好首评内容
- **配图**：需不需要，需要什么类型（数据图 >> 概念图 >> 无图）
- **回复预案**：预测 2-3 条最可能的反对意见，并起草你的回应。
  发布后前 30 分钟的回复互动决定这条帖子能不能进推荐流。

## 输出

```
【事实核查】
  ✅ 已核实：…（附来源）
  ⚠️ 待补来源：…
  ❌ 建议删除（无法核实且非必需）：…

【钩子变体】
  A [反共识] …
  B [具体损失] …
  C [信息差] …

【正文修订】
  <完整修订稿，改动处用 > 标注理由，或直接给干净稿 + 改动清单>

【发布】
  时间：… （理由：…）
  首评：…
  配图：…
  回复预案：
    反对1 → 回应1
    反对2 → 回应2
```

最后写入 `data/drafts/YYYY-MM-DD-HHMM-post.json`，含 `publish_cmd`。

## 边界

- 不自动发布。
- 不替你编数据来让论证更有力。
- 如果你的初稿方向本身有问题（选题过了时效、角度没有差异化），**直接说**，
  不要在烂选题上做文字抛光。
